# Text2CAD 原生分数检索失效原因深度分析

日期：2026-11-12。执行：GLM 5.3。任务：回答"弱检索结果说明了什么——是这条路线行不通，还是 Text2CAD 模型的问题，还是 Text2CAD 数据集的问题"。方法：既有证据的逐层归因 + 一组**先冻结定义、后运行**的零前向 CPU 诊断（复用已认证的 G4 完整分数矩阵；全部结论 exploratory）。本文不改变任何已审核结论。

---

## 0. 结论摘要（先给答案）

1. **"这条路线就行不通"不成立**。正确文本对固定候选的分数显著高于错配文本（R@20 2.609% vs 严格错配期待 0.246%，10.59 倍；置换 p=1/5001）；P0/P1 在另一个生成模型（CadQuery 线）上复现了条件敏感性；图像域同构方法（Diffusion Classifier / DiffusionITM）证明这类读出可行。失效的是**裸 SUM 这一种读出方式**，不是"生成模型分数不能用于检索"这个命题。
2. **主因高度指向"读出失配 + 候选先验淹没"，且今晚的扣除实验首次给出了正方向证据**：分数矩阵 99.68% 的方差（去除文本行后）由候选共同项承载。把候选基线扣掉后（残差读出），**R@20 从 2.609% 升到 3.605%、MedR 从 3411.5 降到 671（5.1 倍）、75.3% 正例排名改善**（中位改善 1,447 名），unique 文本组 R@20 从 2.46% 翻到 5.36%；而只去长度不去其余先验（v5）则把 R@1 打回随机期望水平（0.0126% vs 随机 0.0124%）。信号确实在"相对候选基线的残差"里。**措辞边界（验收订正）**：我们观察到的是与 DiffusionITM 动机一致的**候选背景效应**（候选平均条件分数可作背景、扣除后中段检索改善），不是"复现了 DiffusionITM 的失败机制"——其背景是同候选无文本差分，测量对象与我们的经验平均分不同，且 v5 的变化不能被因果拆分为长度/非长度贡献（§4）。
3. **Text2CAD 数据集有真实的结构性缺陷，但"数据完全不可检索"被外部证据否定**：**不同过滤协议下的外部参照**（IMMA，arXiv 2605.05572；其 test 为点云可转换过滤后的 8,023 个，与我们 8,046 非同库，逐 UID 对齐未核验）达到 R@1 9.71 / R@20 46.85（MedR 25），提示该数据族可支撑强得多的检索；但同时它也说明：**要利用这份数据，判别训练或更强的读出是必要的**，裸生成似然远不够。数据集的三个具体问题（L0 文本信息量低且模板化、DeepCAD 近重复设计、单 UID 标签低估语义相关）各有人群的证据，分别在 §3.3 拆解。
4. **模型因素是真实的第三成分**：训练目标是带 label smoothing 的序列生成，模型从未被优化去"区分两个候选"；它的条件注入是生成式的，零样本检索属于 out-of-scope 使用。弱是预期内的；问题是弱多少可被读出校正挽回（§4、§6-E1/E4），以及换 checkpoint（CADmium）信号是否更强（§6-E5）。

一句话：**这是"路线可行、读出未做对、文本与标签有结构性弱点、模型未经判别训练"四者叠加的复合结果，其中"读出失配"是当前证据最强、且成本最低可检验/可修复的一项。**

## 2. 失效的机制画像

把一次检索拆成"模型有什么信号 → 读出如何提取 → 数据允许什么"，G5 结果对应：

- **信号存在但小**：正确文本带来的分数增益真实存在（10.6×、87.96% 胜率），但它在分数总方差里只占残差部分（~0.32%），相对候选间先验差异（99.68%）小两个数量级以上。
- **跨候选比较 = 大信号减大信号**：同一文本下候选间分数差主要由"这个 CAD 好不好预测"（长度、构造模式、token 先验）决定；文本匹配的增量叠加其上，就像在米尺上读毫米。
- **长度是候选先验的最大可解释成分**：col-effect 与长度相关 −0.757（越短分越高）；长度分层 R@20 从 4.9% 到 0.31% 的塌陷与之自洽。MEAN 没有解决问题，因为按 token 均值重排会引入新的偏差（覆盖反而缩窄到 379 个 CAD）。
- **Top20 不等于全排名**：全排名 Spearman 0.9688（与查询无关排序）但 Top20 交集中位组为 0——文本信号集中在排名头部附近的局部重排，这就是 2.6%@20 但绝对值低的结构。

## 3. 三个假设的逐项裁决

### 3.1 H1：路线（生成似然做检索）原理上不可行？

**不支持**。逐条证据：
- 信号存在性：10.6× 错配对照 + 置换 p=1/5001 + P0/P1 跨模型复现。若路线原理失效（如条件完全不影响似然），这些应接近 0。
- 图像域先例：Diffusion Classifier（ELBO 读出做零样本分类）、DiffusionITM（去噪改善读出做检索）证明"生成分数读出匹配信号"在原则可行——且 DiffusionITM 恰恰记录了同样的失败模式（跨图像直接排序偏向易去噪图像）与其修法（同对象 text vs no-text 差分）。我们的残差/边际校正正是其自回归对应物。
- PMI 视角：理想概率模型下 `log p(C|T) − log p(C) = log p(T|C) − log p(T)`，固定 T 时即"这个 CAD 解释这段文本的能力"。裸 SUM 缺了 `−log p(C)` 项——这是读出错误，不是路线错误。
- 需要诚实标注的边界：即便读出正确，文本侧信息量不足时检索上限仍低（见 3.3 的 L0 问题）。所以"路线可行"指"信号可提取"，不承诺"高绝对命中率"。

### 3.2 H2：Text2CAD 模型的问题？

**部分成立，但"模型没学到对齐"不成立；成立的是"模型没被训练去做判别 + 训练目标抑制了跨候选可比性"**。
- 训练目标：`label_smoothing=0.1` 的 masked CE（官方 loss.py，资产审计记录）。label smoothing 惩罚过度自信，使所有候选的 logprob 偏向"平滑高熵"——这对生成是好的正则，对跨候选似然比较是系统性偏置（先验强的序列被少罚）。这部分是**读出层可校正的模型因素**。
- 架构与训练任务：BERT 编码 + cross-attention 注入，训练只要求 `p(序列|文本)` 高，从未要求"区分两个候选的似然差"。零样本检索是能力的外推使用，弱是预期内的。外部参照（IMMA，不同过滤协议 8,023 test、判别式训练）达到 R@1 9.71%——与裸 SUM 的 ~0.2% 差距提示判别训练与读出方式带来数量级差异；**确切归因（训练 vs 读出 vs 过滤协议）需同库实验，当前只能作外部参照引用**。
- checkpoint 特异性待检验：CADmium（JSON 序列、代码 LLM 底座、MIT/Apache 许可）可做同协议小样本对照（§6-E5）。若 CADmium 读出显著更强，则 Text2CAD-v1.0 checkpoint 是主要瓶颈；若同样弱，指向读出/数据层。
- "模型完全没利用文本"被否定：87.96% 平均胜率意味着条件注入真实改变了逐 token 分布；只是幅度不足以在 8046 候选间形成正确全序。

### 3.3 H3：Text2CAD 数据集的问题？

**三个具体缺陷各自成立，但都不能单独解释全部失效**：
1. **L0 文本信息量低且模板化**：L0 是 VLM（LLaVA-NeXT）从渲染自动生成的一句话抽象描述，无人工逐条校验；一句话难以区分 8,046 个设计中的同类变体。证据：unique 文本组 R@20 也只有 2.46%。**但**：错配对照在同层文本上进行，模板化不解释 10.6× 的正信号；L3（详细几何文本）未测，是关键未做对照（§6-E3）。
2. **DeepCAD 近重复设计**：家具类大量几何近邻；近重复粗筛显示 224 对中 103 个 token-Jaccard≥0.5（P1 线；G4 线同结构）。单 UID 标签把语义近邻当负例 → R@K 系统性低估语义可接受度。**但**：这解释"指标偏低估"，不解释"命中排名低"；UID 上限分析（80.4% vs 2.6%）排除了纯标签噪声解释。
3. **数据清洁度**：v1.0 CSV 缺 100 个 test UID、12 条空 L0；文本由 LLM 两阶段自动生成。这些都是已知并已固定的协议例外，影响小。
4. **反证（最有力，按外部参照口径）**：IMMA 在该数据族的过滤后 test（8,023，非同库）上达到 R@1 9.71——提示数据族可支撑数量级更强的检索。因此"数据集问题"的正确表述是：**这份数据作为生成训练集良好，作为单标签检索真值偏弱（低估语义），且 L0 层信息量天然受限；它不是"不可检索"的数据。**

## 4. 今晚新增的零前向诊断（冻结定义见脚本 docstring；全部 exploratory）

定义（写于查看结果前，`experiments/scripts/analyze_text2cad_failure_factors_20261112.py`）：
- **v2_additive_residual**：双向加性分解 `M ≈ grand + row_t + col_c` 后按残差排名（DiffusionITM 式候选先验扣除的自回归对应物）；
- **v3_halfsplit_marginal**：唯一文本随机对半（seed 20261112），半区外候选均值作基线 `M[t,c] − b_半区外(c)`（避免 in-sample）；
- **v5_length_residual**：每文本行内对长度做 OLS 残差排名（检验"只剩长度"还是"长度之外还有候选先验"）；
- 绑定门：8 项冻结输入 pins、G4 全部 chunk SHA + 头部绑定、**v0 排名与正式 G5 7934 条正例 rank 逐条一致**、共同效应三个统计量复现 10-04 认证值（99.6824% / −0.757 / 87.959%）后才计算新变体。

结果（一次运行实际 exit 0；绑定门全过：8 项输入 pins、G4 全 chunk SHA+头部绑定、v0 排名与正式 G5 **7934/7934** 逐条一致、共同效应三统计量复现认证值 99.6824%/−0.757089/0.87935；运行 395 s 矩阵加载 + 每变体 ~2 s）：

|---|---:|---:|---:|---:|---:|---:|---:|---:|
| v0_sum（=正式 G5） | 0.2017 | 0.9201 | 1.6385 | 2.6090 | 3411.5 | 2.463 | 2.698 | 4.918 / 0.306 |
| v1_mean（G5 诊断） | 0.1134 | 0.6680 | 1.0965 | 1.7141 | 2449.5 | 2.230 | 1.400 | 0.786 / 4.135 |

正例排名迁移（相对 v0）：v2/v3 下 **75.3% 正例改善**（中位 −1,447/−1,449 名），只有 ~24.7% 恶化；v0 原 top-20 正例仅 15.5% 保持 top-20，但 top-20 正例总数 207→286（v2）。v5 下 59.7% 正例恶化、原 207 个 top-20 正例**全部跌出**（0% 保持）。

解读：

1. **扣除候选基线（v2/v3）一致改善中后段检索**：R@5/10/20 全部上升、MedR 5.1 倍改善；最大收益在单例文本（3,005 个单例文本组的 R@20 从 2.463%→5.358%，Top-20 命中 74→161；原 SUM 在这组的 MedR 为 4,944，是全组最差）。**重复文本侧 Top-20 命中反而下降**（重复文本下的 4,929 条查询、对应 639 个文本组：133→125/123）：收益几乎全部来自单例文本。验收方补充的文本组配对重抽样（3,644 组、5,000 次、seed 20261112）在这份已看过的矩阵上支持 v2/v3 的 R@20 增益（**+1.00pp [0.35, 1.66]** / **+0.96pp [0.32, 1.62]**），R@1 两个区间均跨零。这验证 §2 的机制画像：文本信号存在于"相对候选基线的残差"中，被候选共同项压制；信号强度不足以改变 top-1 构成。
2. **v3≈v2（3.57 vs 3.60）说明基线可由半样本稳定估计**：候选先验是候选自身的稳定属性，用 validation 一半文本即可估出——这为 E1 的确认性实验（validation 冻结 → test 对照）提供了可行性依据。
3. **v5（只扣长度）几乎清零信号（R@1=0.0126% ≈ 均匀随机期望 0.0124%）**：裸 SUM 里正例的"长度优势"是主要假信号（正例平均更短、更好一句话描述），而**非长度的候选先验部分是负贡献**。两者方向相反：全扣（v2）净收益为正；只扣长度（v5）失去拐杖、暴露负贡献 → 崩到随机。这也解释了 MEAN 的失败机制（MEAN≈只动长度标度：破坏长度拐杖、又没扣掉其余先验 → R@20 1.71%、unique 层更差）。
4. **长度分层完全反转**（v2 下最长层 5.36% > 最短层 2.02%）："短=分高"确实与匹配无关，是纯先验效应。
5. **R@1 略降（0.202→0.164）**：校正改变 top-1 构成（v0 top-20 正例仅 15.5% 保留），收益集中在中段排名；top-1 竞争由"最近重复设计"决定（近重复候选与正例先验几乎相同，扣除后区分不开——与 P1 的 q12/q13 现象同源）。
6. **上限视角**：校正后 R@20=3.6% 仍远低于外部参照 IMMA（不同过滤协议，判别式训练）46.85%——读出校正挽回的是"被先验淹没的那部分信号"，剩余差距由文本信息量（L0）、模型判别能力、单标签口径承担（§6 E1–E5）。
7. **实现注记（数据保真度）**：分数矩阵若以 float32 重建会把部分不同的 float64 分数塌成同分，导致 503/7934 条正例排名与正式件不符（绑定门当场拦下）；换 float64 后 7934/7934 逐条一致。后续任何复用矩阵的分析必须全精度。另：严格胜率 87.9591% 的分母是其余 3,643 个其他文本组（验收复核恢复）；本轮以 3,644 行为分母复算得 87.935%，差异即分母口径，无碍结论。10 月报告的置换 p=1/5001 属于整套 R@20 错配对照，不是单指标检验。

## 5. 证据-假设判定表

## 7. 对三个问题的直接回答

1. **是这条路线就行不通吗？** 不是。条件对齐信号跨两个模型、两种读出对照稳定存在；图像域同构方法可行；任务在同数据上被判别模型解到 R@1 9.71%。失败的是"裸 SUM 跨候选排序"这一具体读出。
2. **是 Text2CAD 模型的问题吗？** 是"模型未经判别训练 + label smoothing 生成目标抑制跨候选可比性"这种**可预期的、部分可校正的**问题；不是"模型没学到文本对齐"。checkpoint 特异性（换 CADmium 是否更好）待 E5。
3. **是 Text2CAD 数据集的问题吗？** 数据集有三个真实弱点（L0 自动模板化文本信息量低、DeepCAD 近重复、单 UID 标签低估语义），它们压低了绝对上限并使指标偏保守；但 IMMA 的同库结果排除了"数据不可检索"。更准确的定位：**Text2CAD 是好的生成训练集、弱的检索真值集**；检索结论要么换真值（E6 盲审多正例），要么换文本层（E3），要么接受"UID 链接检索"的口径并报告其上限。

- IMMA 数字来自 preprint（引用数 ~2，venue 未核验），gallery 构成（8,023 过滤细节）未核验，并表时须声明训练条件差异。
