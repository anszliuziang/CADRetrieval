# Reproduce the 910A witnesses

The host is `yunnao-910a`. Run the following from a fresh Linux shell on that host. The environment and project worktree are staged under the user's work directory. Device assignments must come from the current `npu-smi info` and exclude any occupied or unhealthy chip. The projection from physical IDs to process-local NPU IDs comes from `ASCEND_RT_VISIBLE_DEVICES`. Each command has a timeout and publishes its actual exit code.

```bash
set -euo pipefail
RT=/home/ma-user/work/CADRetrieval_runtime
PY="$RT/envs/cadretrieval-910a-cann80-torch240/bin/python"
cd "$QUALIFICATION_CHECKOUT"
test -z "$(git status --porcelain)"
git rev-parse HEAD
set +u
source /usr/local/Ascend/ascend-toolkit/set_env.sh
set -u
export PYTHONNOUSERSITE=1 OMP_NUM_THREADS=2 TORCH_DEVICE_BACKEND_AUTOLOAD=0
test "$NPU_A" != "$NPU_B"
mkdir "$WITNESS_OUTPUT"
npu-smi info > "$WITNESS_OUTPUT/npu_before.txt"
for chip in "$NPU_A" "$NPU_B"; do
  grep -q "No running processes found in NPU ${chip}" "$WITNESS_OUTPUT/npu_before.txt"
  grep -qE "^\|[[:space:]]+${chip}[[:space:]]+910ProA[[:space:]]+\|[[:space:]]+OK" "$WITNESS_OUTPUT/npu_before.txt"
done
cd "$QUALIFICATION_CHECKOUT"
for mode in fp32 fp16 bf16-capability hccl; do
  visible="$NPU_A"
  cmd=("$PY" -B -u experiments/scripts/probe_yunnao_910a.py "$mode" --precision preserve)
  if [ "$mode" = hccl ]; then
    visible="$NPU_A,$NPU_B"
    cmd=("$PY" -B -m torch.distributed.run --standalone --nproc_per_node=2 experiments/scripts/probe_yunnao_910a.py hccl --precision preserve)
  fi
  printf '%q ' "${cmd[@]}" > "$WITNESS_OUTPUT/$mode.argv"
  date -u > "$WITNESS_OUTPUT/$mode.start"
  set +e
  timeout --kill-after=20s 240s env ASCEND_RT_VISIBLE_DEVICES="$visible" "${cmd[@]}" > "$WITNESS_OUTPUT/$mode.stdout" 2> "$WITNESS_OUTPUT/$mode.stderr"
  rc=$?
  set -e
  printf '%s\n' "$rc" > "$WITNESS_OUTPUT/$mode.exit"
  date -u > "$WITNESS_OUTPUT/$mode.end"
done
npu-smi info > "$WITNESS_OUTPUT/npu_after.txt"
```

This records hardware capability and small operator checks. The model replay in the development plan provides the Text2CAD acceptance evidence. Match the pilot's inputs and precision separately before making a claim about a different checkpoint or training workload.
