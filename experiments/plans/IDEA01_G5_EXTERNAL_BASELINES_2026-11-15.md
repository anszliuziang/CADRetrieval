# Text2CAD G5 同协议对照计划

2026-11-15。目标是在已完成的 G5 评测上补齐三个论文方法的实测，再用受控对照判断差距与输入表示、检索训练、生成评分的关系。GLM 负责实现和交付，Codex 复核代码、评测口径和结果。正式模型评分按 [项目运行准入](../../CLAUDE.md) 和 [ACTIVE_TASK](../ACTIVE_TASK.md) 执行。

## 1. 共用的评测协议

沿用 G5 的 Text2CAD v1.0 Protocol A。固定 **7,934 条原始 L0 查询、3,644 个去除首尾空白后的唯一文本、8,046 个官方测试 CAD UID**。每条原始查询等权，唯一正例为其登记 CAD UID。各方法可使用同一 CAD 的命令序列、渲染图、点云或 B-Rep。每种表示都保留到原 CAD UID 的对应关系。

- **身份与数据。** 复用 [G5 冻结配置](../configs/text2cad_g5_cpu_frozen_20261003.json) 中的 query、gallery、qrels 和查询映射 SHA。评分端读取查询文本和候选资产，配对关系由评价端使用。候选侧使用几何或由几何生成的资产，避免把其配对 L0 文本当成图库描述。
- **分数接口。** 各方法按唯一文本和 CAD 产出分数，附行列身份、分数方向、数值精度和输入指纹。接受有完整身份映射的数值矩阵或分块文件，允许按行读取。统一入口校验覆盖、唯一性和有限性，按方法声明的方向排序，完全同分按原 `cad_index` 升序。全库结果应覆盖 29,319,624 对，映射回 7,934 个正例名次。
- **覆盖。** 先以 8,046 件 CAD 为目标验证覆盖。若存在确实无法转换的 UID，保存缺失清单与原因。在读取新方法的检索指标前固定公共子库和正例仍在该库中的查询。所有比较行在相同子库重排，包括从 G4 已有矩阵切出的 SUM。表中明确写图库大小、原始查询数和覆盖率。
- **统计。** 共用 R@1/5/10/20、MedR 和 G5 的并列规则，保留逐查询正例名次和每个唯一文本的 Top-20。报告唯一文本、重复文本和已有 CAD 长度分层。正式比较使用同一组 5,000 次文本组 bootstrap 抽样，计算相对 SUM 的配对差与 95% 区间。主表召回率用百分比，注明单位。

原协议和分层定义见 [G5 预注册](IDEA01_M1C_G5_CPU_EVALUATION_2026-10-03.md#冻结排序和指标)及 [G5 最终报告](../submissions/idea01_text2cad_benchmark_20260928/CODEX_TEXT2CAD_FULL_RETRIEVAL_RESULTS_2026-10-03.md)。

## 2. GLM 的第一项交付

**实现统一 CPU 评价入口，并用已完成的 G4 分数逐条复现 G5。** 优先复用 `score_ranks`、`rank_metrics` 和查询分组逻辑，给外部预计算分数增加薄入口。历史正式 CLI 及其准入逻辑作为原运行证据保留，验收回放使用独立的新输出目录。相关代码见 [G5 评价模块](../src/text2cad_g5_cpu.py)和 [原执行入口](../scripts/run_text2cad_g5_cpu.py)。

1. 从 `experiments/runs/idea01_text2cad_g4_full_20261002/` 读已认证的 chunks 和清单。用冻结配置核对输入及映射指纹，以 `experiments/runs/idea01_text2cad_g5_cpu_20261003/query_ranks.jsonl` 和 `metrics.json` 为历史真值。对齐 `query_id`、正例 CAD UID 和 SUM rank 三项，要求 **7,934/7,934** 全等。使用旧 ranks 作为核对对象，从旧 scores 重新算排名。
2. 按命中数与原始分母核对 SUM 指标。R@1/5/10/20 命中数应为 **16/73/130/207**，显示值为 **0.201664%/0.920091%/1.638518%/2.609024%**，MedR 为 **3411.5**。用小型测试覆盖完全同分、重复文本恢复、外部矩阵行列错位及缺失或非有限分数。至少让一个外部格式的替身分数输入经同一评价入口产生预期排名。
3. 做三个方法的接入盘点。逐项记录公开代码和权重版本、现成渲染覆盖、CAD 到点云和 B-Rep 的可用转换入口、UID 对应、设备依赖和缺项。优先核实 CLIP 的渲染资产、建议权重和视角规范。可用现有 CPU 工具时，用少量覆盖 CAD 长度分层的 UID 验证转换与身份连接。本轮工作量为本地 CPU 回放、测试和资产预检，新增模型前向预算为 0。
4. 交付薄入口及针对性测试、一条可复跑命令、实际退出、输入与分数来源指纹、逐查询对账汇总、资产覆盖表和 CLIP 首轮评分所需资源。结论页写清哪个步骤已执行、哪个仅完成准备。轻量报告放在 `experiments/submissions/idea01_g5_external_baselines_20261115/`，运行原件使用新的独立 run 目录。

计划建立时已在本机核到冻结 query、gallery、qrels、评价映射、G4 清单及 G5 历史 ranks 和 metrics 的文件入口。三种几何表示的运行覆盖由本轮预检测定。

## 3. 论文方法的执行顺序

先接 CLIP，再接 OpenShape，最后接 MM-CAD。每个方法在正式评分前固定权重、预处理、输入表示、分数读出及实际设备。先验证少量 UID 到分数的完整路径，再在已冻结的图库上输出实测。各方法评价 G5 时使用纯 L0 文本作为查询。

| 顺序 | 对照 | 接入重点 |
|---|---|---|
| 1 | CLIP 与固定视角 CAD 渲染 | 建议以公开 ViT-B/32 为首选，预检后固定权重、视角、图像预处理和多视图聚合。核对渲染覆盖及 UID。图像和唯一文本各编码后计算相似度。 [官方实现](https://github.com/openai/CLIP) |
| 2 | OpenShape PointBERT | 选择官方 PointBERT checkpoint 及其匹配的文本编码器。固定表面采样、朝向和归一化，先核对实际设备可用的算子。 [官方代码与权重](https://github.com/Colin97/OpenShape_code#checkpoints) |
| 3 | MM-CAD 纯文本到 B-Rep | 用官方联合 checkpoint，先验证 G5 STEP 到兼容特征及图库向量的完整路径。官方示例以预计算向量作为图库输入。 [官方代码与权重](https://github.com/exanos/MMCAD#pretrained-models) · [推理入口](https://github.com/exanos/MMCAD/blob/main/inference.py) |

主表顺序为均匀随机或固定随机、长度升序、长度降序、Text2CAD SUM、CLIP、OpenShape、MM-CAD。每行记录 CAD 表示、权重版本和训练来源，填同一评价入口的实测结果。E2 的候选均值校正保留为同库探索性读出，注明背景估计使用的文本范围。用逐查询和 Top-20 证据复核汇总表。历史 G4 分数直接用于我们的行。

若某个方法遇到转换、权重或设备问题，保留失败证据和覆盖，继续其他可独立推进的对照。已跑通的行可以先交阶段表，缺项标为待测。完整对照以三条外部方法在同协议下的实际结果为准。

## 4. 解释差距与新生成器对照

- **先定位错在哪。** 比较各方法在唯一文本、重复文本和 CAD 长度分层的正例排名。复用已有 G4 文本错配诊断和 E2 候选背景诊断。用双方差异最大的少量查询核对前列候选，区分登记 UID 歧义、CAD 几何偏差与候选背景分数偏差。登记 UID 主表继续以原标签计分。 [已有矩阵诊断](IDEA01_TEXT2CAD_EXISTING_MATRIX_DIAGNOSTICS_2026-10-04.md) · [E2 订正结果](../submissions/idea01_next_phase_20261112/E2_RESULTS_2026-11-14.md)
- **补同命令序列对照。** 三个外部系统同时改变表示和训练方式。按 IMMA 表 II 的思路增加一个用同类命令序列的检索训练基线。训练、超参数选择和测试按冻结划分执行。若采用按论文实现的版本，在表中标明实现来源。该结果检验同类表示在检索监督下能达到什么水平。 [IMMA 表 II](https://arxiv.org/html/2605.05572v1)
- **再检验更换生成器。** 优先选有可核验权重、训练 UID 和原生候选打分入口的模型，并尽量保持 CAD 表示接近。以同一组查询及候选比较**旧模型／新模型 × 原生分数／预先固定的校正分数**。在开发数据上确定校正，先固定一个覆盖可验证、预算可估的小库，两套模型用一致的查询、正例和负例。旧模型从 G4 切片重排。预算和初步结果支持时按正式准入推进全库。若表示或训练来源也变了，按完整系统差距解释。

第一轮同协议表用来判断其他方法是否明显领先。只有经过后续同表示和评分对照，才把差距收窄到具体因素。生成质量指标用于选择候选生成器，检索差距由固定图库排名测量。
