# 实验一执行文档｜冻结 Text2CAD 在 Fusion 360 上的跨来源检索

2026-11-19 修订 v1.1。交接标识 `idea01_e1_fusion360_retrieval`。本地 Git 交接分支为 `codex/e1-fusion360-protocol`。执行者在 `inputs.json` 分别记录交接时给出的完整方案提交 SHA 和后续实际运行的实现 SHA。

**本实验让同一个冻结生成器先后面对两座等大的图库。** 一座来自训练使用的 DeepCAD/ABC 来源，另一座来自 Autodesk Fusion 360 Gallery。两座图库都使用 CADmium 团队根据建模程序生成的专家风格描述。文中简称“专家文字”。独立人类需求另需采集。给定文字，模型逐一评分并排序所有候选命令程序。我们分别测原生分数有没有跨来源匹配信号、源域选定的校正能否迁移、相同模型对措辞与精确量值有多敏感。

**接手后的第一件事。** 在项目根目录阅读 [CLAUDE.md](../../CLAUDE.md) 与[当前任务状态](../ACTIVE_TASK.md)，接着做第 3 节的输入清点和第 4 节的源验证转换。首个可验收产物是带哈希的资产清单、两域样本覆盖表和源验证的几何重放记录。现有模型评分组件和 G5 矩阵可以复用。新的 Fusion 候选读取、两种文字改写与 E1 评价入口需由执行者实现。正式作业按项目既有 Git 交接、指定 SHA、设备和预算流程执行，给本 E1 单列 run_id 及账本。本分支的任务文件给出 E1 入口并保留此前运行记录。E1a 从本地 CPU 清点与转换开始，正式评分的 SHA、设备与预算由 E1 单独登记。研究负责人要在看到实验一结果后再确定实验二。

## 1. 问题、证据与比较设计

用生成似然做分类时，固定一件观测，比较哪种文字条件更能解释它。在这里，最接近这一想法的是固定同一个 CAD、对多条文字排名。实际的文字找 CAD 则要固定文字、改变候选程序。有些程序在许多描述下都容易生成，所以本轮同时测正向、反向及扣除候选背景后的正向排名。实验一全程给已有候选打分，生成实体是否满足同一要求留到实验二再测。

开工前的独立评审提出了一个具体反例。假设每件零件都有一个罕见的精确尺寸，仅凭这个数值就可能同时通过正向检索、反向检索和二件配对。因此本轮既测原生条件分是否能跨来源找回实例，也在同一批零件上改变措辞和量值，再用最终实体核查前排结果。三项观察共同决定下一轮要控制哪种几何属性。

| 要回答的问题 | 预先指定的证据 | 支持的表述 |
|---|---|---|
| Q1 原生条件生成分在外域能否找回登记实例？ | Fusion 主图库原生分 `S₀` 的 R@20，对同一矩阵的查询–正例标签置换。优先解读这一行 | 在本模型、专家描述、共同命令表示和指定图库规模下，原生条件分含跨来源实例匹配信息 |
| Q2 源域定好的评分法能否迁移，是否有改善？ | Fusion 上 `S₄₈` 的 R@20 对置换。对同一查询另算 `S₄₈` 相对 `S₀` 的命中率差及区间 | 前者回答校正方法的迁移，后者量化改变评分带来的收益或损失 |
| Q3 哪些现象能帮助解释结果？ | 相同 CAD 更换文字、反向检索、难配对、无需生成器的表面线索基线、48 条文字干预与语义盲评 | 能区分若干竞争解释，指出下一轮值得单独验证的属性。逐个属性的生成–辨别关系留给实验二 |

| 行 | 查询 | 候选、评价单位与用途 |
|---|---|---|
| A · 同源短描述 | Text2CAD v1.0 官方 `abstract`（L0） | 与 B **相同的候选、命令编码和顺序**。L0 非空且可完整输入的 UID 作为查询，其余候选仍留在库中，另记缺失或超长原因。A 的 L0 如与训练或库内其他 L0 同文，标记并分层报告。B 的入库条件由专家原文和 CAD 决定。A/B 差值只在同时有两种文字的 UID 上计算 |
| B · 同源专家描述 | CADmium-ds 的 DeepCAD 官方 test 专家原文 | 每件候选一条专家查询。与 A 一起看换文字，与 C 一起看相同标注流程跨几何来源 |
| C · 目标域主结果 | Fusion360-ds 专家原文与 Autodesk Reconstruction 官方 test 的交集 | 每件候选一条专家查询，项目分组后抽样。每条查询对 C 的所有候选评分 |

**零样本的口径。** Text2CAD 生成器和全部权重冻结，背景文字、校正公式、转换容差与评分选择在源域确定。目标域的文字和程序可用于建索引、按预定规则构造测试集及评价。目标检索标签、测试查询总体统计、排名和失败例不参与评分法选择。两域专家文字与原建模过程有关，几何来源变化与人类独立提出需求是两个问题。B/C 中的零件不同，因此两域差值还可能包含复杂度、查询难度与图库组成。这里没有“未见类别”的训练/测试划分。

**历史参照。** G5 的 7,934 条 L0 查询、8,046 件图库上，原生和校正 R@20 分别为 207/7,934（2.61%）与 462/7,934（5.82%）。历史自然难配对中 960 个目标组成的 3,776 对按组合等权有 80.22% 选对整组。两者都是提出新问题的依据。A 在本轮子图库中重排后才能与 B 比较。对于新外域，不预设应达到的命中率。

## 3. E1a · 建候选母集并排查训练暴露

**先对账再筛选。** 每个域先完成左连接，保留完整 UID、项目、原文 SHA、句长与程序指纹。DeepCAD UID 的斜杠和前导零参与匹配。Fusion 项目 ID 取 Autodesk UID 的第一段。BERT 用固定 tokenizer、含特殊符号、关闭截断来计长。进入评分时验证有效输入与这次计数一致。下表的数是前期资产审计的检查点，最终样本还须过量化、几何和分组。

| 检查点 | 源 DeepCAD 专家 test | 目标 Fusion |
|---|---:|---:|
| 发布件数／与原测试清单对上 | 8,046 / 8,046 | 8,307 / 1,661。其余 6,646 位于 Autodesk 官方 train |
| 测试交集中完整文字 ≤512 token | 7,606 | 1,370（291 条超长） |
| 以上样本中，几何程序字段与 CADmium-ds 源 train 相等 | 2,051 | 29 |
| 通过上述两项 | 5,555 | 1,341 件、943 个 Autodesk 项目 |
| 再通过历史 Text2CAD 公共训练量化张量排查 | 4,753（源官方向量口径） | 待本轮重编码 |

可在根目录运行下面的只读检查确认第一层连接。后续清洗仍需程序解析、原文和几何哈希、量化与实体重放。

```python
import json
from pathlib import Path
import pyarrow.parquet as pq

cache = Path(".cache/crossdomain_survey_20261119")
fusion = pq.read_table(cache / "fusion360-ea7d06f.validation.parquet", columns=["uid"])
uids = set(fusion.column("uid").to_pylist())
split = json.loads((cache / "fusion-original-train_test.json").read_text(encoding="utf-8"))
assert fusion.num_rows == len(uids) == 8307
assert len(uids.intersection(split["test"])) == 1661
assert len(uids.intersection(split["train"])) == 6646
```

1. **文本与几何原件去重。** 查询与公开源训练文字做 strip 后的逐字比较。分别对 Text2CAD 公开 train 的 `abstract, beginner, intermediate, expert` 四个发布字段和 CADmium 训练专家文字建索引，命中时记来源、字段和 UID。A 行另按第 1 节保留同图库。逐 CAD 仅保留每个 `parts` 内的 `coordinate_system, sketch, extrusion`，保留各级部件、面、环和曲线标识。用于查重时递归按键排序，紧凑 JSON、UTF-8、无额外舍入，核验相等串再记重合。用于执行时保留原建模顺序。候选输入始终只来自该 CAD，描述、UID、派生尺寸摘要和参考文字不能拼入模型候选。对 118,299 条源训练专家程序的这一判据应复得全部 Fusion 的 133 个重合 UID，其中官方测试 29 个。
2. **原生量化去重。** 与官方 Text2CAD 公开 train（159,049 UID）核查 `cad_vec`，用连续小端 int32 的 `272×2` 字节取 SHA-256，与历史口径相同。B 保存官方、重编码两种向量的指纹并报告各自检出的重复。主样本排除任一已知源训练精确重合。C 对重编码向量执行同样检查。另给整个输入包的指纹，覆盖 flag、index、两种 mask，供历史分复用核对。分别列明“公开源文件已查到的重合”和“模型实际训练履历可追溯程度”。
3. **家族与近似程序。** 同域内的精确等价程序、已知同一原始设计和人工确认的近复制件建连通组。Fusion 加入同 Autodesk 项目的连接。DeepCAD 使用可确证的设计来源或近复制簇，数字 UID 目录前缀不作为项目。为在大规模源训练上排查疑似近复制，建议按部件/操作直方图、草图原语与相对尺寸粗筛，取每件最接近的 5 个源训练候选（并列按 SHA 排序），再复核程序或几何。保留近邻规则、覆盖、指纹和证据。确证的训练副本从主要清单剔除。仅形状常见或相似的标记 `suspected`，保留主结果并另外报告排除此层的敏感性。B/C 之间确认完全相同的测试实体也单列，从主比较的 C 母集剔除以保持来源分离。所有决定在看分数前作出。
4. **逐级分母。** 为每件原始 CAD 写 `all_reasons` 和固定顺序的 `first_exclusion`。顺序为划分/UID、缺文字或超长、源训练文字/程序/量化精确重合、不可解析或不支持、序列超长/失效、参考几何不合格、已证实近复制、分组抽样。量化不可得时留空、保留其失败原因。保存每步人数/项目数、相同 CAD 不同文本等价数以及源/目标复杂度分布。超长样本限制推论的人群范围。入选查询的失败要按其实际输入解释。

**Autodesk 的组件划分与项目隔离。** 初筛后 1,341 件来自 943 个项目，其中 596 个项目在 Autodesk 官方 train 也有组件。本轮 E1 的生成器和校正法均未在本实验使用 Autodesk train 做开发，仅凭同项目出现在这个划分中，不剔除这 596 个项目。将全部 C 测试及预留组里的 Autodesk 项目 ID 和已确认的跨项目近复制家族写入隔离清单。今后若从 Autodesk train 选开发数据，先按这份清单排除整组，记录过滤前后数量与交集为零。后续模型若已在这些项目上训练，另标该模型的暴露范围。

## 4. E1a–1b · 两域的编码对照与几何核验

从源 **validation** 选 64 件独立开发零件，覆盖单/多部件、新建、合并、切除。按源验证 UID 哈希取样，列出各操作实际覆盖与无样本的类别。另做有已知错误的对照，例如在有切除的样本删除该操作、改变非对称件的一次挤出深度。在源端检查错误构造确实改变实体。这批开发件、背景文字、B 的测试和 C 的测试使用不同用途标识。

- **重建路径。** B/C 主输入统一从 minimal 程序生成。官方的 `from_minimal_json` 返回 `bbox=None`，而整件 `normalize()` 第一步就会读取包围盒。官方 minimal 导出先做全局归一化，再把局部草图从量化网格尺度还原。实现者在 64 件源验证零件上验证草图回到网格的变换、挤出平移/尺度、布尔操作和 8-bit 量化顺序。将最初原程序、浮点实体和量化重放分开保存，逐项比较 `cad_vec`、`flag_vec`、`index_vec`、`key_padding_mask` 和规范因果/START 掩码。超过 272 行且无法保义的候选计入覆盖损失。仅为绕过空包围盒补一个单位框再全局归一化，会改变已有尺度。[官方 minimal 导出逻辑](https://github.com/SadilKhan/Text2CAD/blob/669a81472ede2269837c22a4d00070eaac360c82/CadSeqProc/cad_sequence.py)
- **独立几何核验。** C 对 Autodesk 同 UID 的最终 STEP，B 至少要对同 UID 官方向量重放的实体，有独立原生参考实体时再作一次对照。两种参照分别记覆盖。记录参考文件的来历。由同一转换器生成的两份几何只能做一致性检查。解析 Autodesk 原生 JSON 时长度为 cm、角度为 rad。STEP 按文件单位与内核的换算读取。统一到公共坐标，使用有来源的刚体变换与单一尺度，保留手性、部件关系与长宽比。记录变换、参考框与失败原因。
- **建议的初始几何门。** 两边均可执行且实体数相同，相对体积差 ≤5%，双向表面距离各自 99 分位均 ≤参考包围盒对角线的 1%。按面积确定性采样（建议每边 16,384 点，点到对面三角面或解析面），固定网格精度与 UID 派生种子。记录连续误差。检查已知损坏样本，尤其是体积变化很小但孔通盲改变的情形。适用时以穿透/截面观测作局部复核。仅在源验证阶段修坐标或设定容差，将最终指标、样本、阈值及理由写入冻结清单。所有入选件逐件检查。
- **区分重放与再编码。** 在历史官方张量上先重放 16 条 L0 × 16 件，按旧口径逐分核验 `|ΔSUM| ≤ max(10⁻³, 10⁻⁶ × |SUM_ref|)` 以及有效字段数相同。在可分辨名次上复核排序，近并列列出。这个检查验证评分器。另以预抽的 **256 条 B 专家查询**、整个 B 图库，比较**官方张量**对**重编码张量**的 R@20 配对差和名次变化，这才验证转换对检索的影响。输入逐字节一致的列可直接复用。
- **源域可检出的编码退化。** 开盲前固定 `n=256` 个独立组的查询和工程容限 `δ_enc=3.125` 个百分点。原生与校正各算一次。设 `u` 为仅官方张量命中的条数，`v` 为仅重编码命中的条数，实测净损失为 `(u−v)/n`。分别对 `u/n`、`v/n` 求 97.5% 双侧 Clopper–Pearson 区间 `[Lᵤ,Uᵤ]`、`[Lᵥ,Uᵥ]`，组合 `[Lᵤ−Uᵥ,Uᵤ−Lᵥ]` 作为独立查询组假设下保守的 95% 差值区间。上界 ≤ 容限说明该诊断排除了超过容限的净损失，下界 > 容限提示明显退化，其余记未决。这项区间依赖对查询组的抽样解释，以图库固定为前提。当 `N=256` 时已覆盖 B 全部查询，同时单列这座有限图库的确切净差。若所有候选的模型输入逐字节相同且完成评分器重放，另记录固定图库上两条路径输入等同的直接证据。

**为什么采用 256 条。** 零翻转时，上述组合区间的正上界为 `1 − 0.0125^(1/n)`。`n=64` 时为 6.6178%，`n=138` 时仍有 3.1255%，`n=139` 时为 3.1034%，`n=256` 时为 1.6972%。这是零翻转下的分辨率。有正反向翻转时按实测区间判读。64 件源验证几何开发样本和这里的 256 条 B 排名查询各有独立用途。

**Fusion 同一件 CAD 的两条输入路径。** 在 C 冻结的图库中预抽 32 个项目，每项目 1 个 UID。对每个 UID 分别读 `r1.0.1/reconstruction/<uid>.json` 的 Autodesk 原始建模历史和 CADmium minimal 程序。两路各自构建量化输入、恢复最终实体，与同 UID 最终 STEP 核验。原始历史路线按其真实 schema 和包围盒执行官方归一化。minimal 路线独立使用本件程序字段。原始程序、STEP 和描述均不得用来给 minimal 路线补目标几何或排序线索。记原件与输入指纹、实体数与误差、有效字段数、首个不同字段、掩码、失败阶段，汇总 `抽取 / 双路可执行 / 双路几何合格 / 模型输入完全一致 / 模型输入不同`。失败的 UID 留在 32 件分母中。已核实 1,341 件初筛候选都能在官方 ZIP 目录找到同 UID 的原始 JSON 和最终 STEP，逐件执行能力仍需测量。

若两路均通过几何核验而模型输入不同，标记差异的 `d` 件（`0≤d≤32`）。按预定诊断在原大小、原顺序的 C 图库中，只替换这 `d` 列为原始历史编码，对所有 C 原文和 48 条背景补算其分数，其余列复用。比较固定 UID 的名次、Top-20 新增/丢失和两种读出的净差，登记件在替换列内、外分别给分母。`d=0` 时无新增打分。此比较只测被替换的列，主表始终使用共同的 minimal 路线。双路几何不一致或解析失败先查格式及几何，保留覆盖损失和不确定性。根据 C 排名选择编码器会改变首次外域检验的含义。

**已复跑的单件编码探针。** `100155_57ec5fc6_0000` 的原始历史经官方 `json_to_vec(bit=8, padding=True, max_cad_seq_len=272)` 产生 8 组草图–拉伸。对 minimal 的独立试算，只用本件的圆心和半径按官方上下右左四点约定补齐圆的 `pt1…pt4`，将挤出数转为 NumPy 浮点数，按每个 `sketch_scale` 的 `255/sketch_scale` 还原局部网格，再量化与填充。两路输入各有 310 个有效目标字段，`flag_vec` 和 `index_vec` 完全相同，但 `cad_vec` 有 **26 个字段**不同，PAD 掩码的位置也有差异。按小端 int32 连续字节计算，原始路线 `cad_vec` SHA-256 为 `477cc0d64afcefc203ada3ec20cf536a2f554f523c09ed40a45662f5a3e2efa9`，本次 minimal 试算为 `e607812977ea6b2d9634cc39147cd699a99d06308a1157e69e8f0368d1ff2dca`。这给出了为何要逐字段复核的实物例子。此适配只是源验证的待检验实现，本例尚未完成独立 STEP 几何验收，也未计算检索排名。[官方圆的读入与编码](https://github.com/SadilKhan/Text2CAD/blob/669a81472ede2269837c22a4d00070eaac360c82/CadSeqProc/geometry/circle.py)

## 5. 选图库、对照子集与开盲边界

先完成筛查、连通分组及几何核验。每域以组作为抽样单位，每组最多一件。哈希为 UTF-8 的 SHA-256，组 ID 取 `sha256((domain + "\n" + "\n".join(sorted(set(member_uids)))).encode("utf-8")).hexdigest()`，无末尾换行，保存成员映射。域串分别为 `deepcad`、`fusion360`。种子 `cad-domain-v1`。消息串取 `seed|purpose|domain|id`。`reserve` 哈希转无符号大端整数，模 4 等于 0 的整组留待后续。其余组以 `select` 哈希排序，组内以 `member` 哈希取第一件。按十六进制摘要升序排列，并列再按原始 ID 字典序。冻结两域清单和候选顺序，杜绝按分数换件。

- B/C 各取 **512 件**。若任一域不足 512 而两域都有至少 256 组合格，两域都取 256。若任一域不足 256，先交覆盖与故障诊断，标明新规模的统计意义，再另定正式主评。A 复用 B 的图库。登记件确实位于该库，每个 B/C 目标恰有一条主查询，在本域封闭图库全评分。
- C 入选组按 `diagnostic` 哈希取前 48 组，做文字干预与原文前排盲评。按另一用途 `fusion-encoding-check` 哈希取前 32 组，做双来源编码诊断。两组可以自然重合，记录交集。B 入选组按 `encoding-check` 取前 256 组（B 只有 256 件时使用全部）。三个用途都对已冻结的稳定组 ID 排序，选样时不读排名。
- 冻结文件记项目分组、保留/排除和留出清单、数据与输入指纹、背景的顺序、术语和数值规则、改写版本或不可改写理由、盲评抽样、主指标、检验、随机种子、设备及实现 SHA。语义编辑可以看原文和几何验证等价性。编辑者不接触模型分数。生成器收到的候选仅含 CAD 输入。查看目标结果后提出的规则另标为探索，新算法若受此轮启发，留出项目只能证明已研究目标域内的新项目泛化。

## 6. E1b–1c · 评分、对照与统计

设 `q` 为一条文字，`c` 为候选程序，`y[t,h]` 为下一行在字段头 `h∈{x,y}` 的真实取值。teacher forcing 时输入真实程序前缀，预测下一行，`M(c)` 为移位后标签非 PAD 的位置与字段。模型在 eval 模式，关闭 dropout。冻结的主评分为

$$
S_0(q,c)=\sum_{(t,h)\in M(c)}\log p_{\theta,h}\!\left(y_{t,h}\mid q,y_{<t}\right).
$$

按现有实现，两个头各有 267 类。逐头用 FP32 的 log-softmax 取真实值，转 FP64 后在有效字段上分别求和，再加总。另存有效字段数。它给当前程序的实际有效字段打分。训练用的平滑交叉熵、按长度平均、几何等价程序的总概率是不同的量。B/C 使用完整合格文本，分数越大排序越靠前。

从第 2 节固定清单恢复 `b₁ … b₄₈`。将每个候选在这 48 条文字下的原生分还原到概率尺度，取算术平均，再取自然对数得到 `B(c)`。它是这批源文字给出的经验基准。扣掉它，可以检验某个候选对当前描述的偏好。每个候选单独计算

$$
B(c)=\operatorname{logsumexp}_{j=1}^{48} S_0(b_j,c)-\log 48,\qquad
S_{48}(q,c)=S_0(q,c)-B(c).
$$

在每个新候选上重算背景。官方张量的旧背景只可复用于完全相同的模型输入。两段 `0…23`、`24…47` 各用自己的 log-mean-exp 得到两个半集校正分，用于检查稳定性。两半与反向检索均从已有分数计算。测试查询不参与背景选择。

**两项可以直接从排名复核的现象。** 对每种打分统计各候选在所有查询的前 20 中出现多少次，给出出现最多的 10 件及其有效字段数、`B(c)` 和命中查询数。如果校正减少了热门候选的集中、相应查询又找回了正确件，就能具体说明分数怎样改变了检索。再按实际送入编码器的 token ID 序列聚合同域主查询。对于含 `m` 个不同登记件的同文组，固定排序最多命中 `min(m,K)` 件，因此 `Σ组 min(m,K) / 查询总数` 是单 UID 的 R@K 在这些重复输入下的可达上界。报告同文组数、涉及的查询数和上界。

**如何读 D。** 假设 `qᵢ` 对零件 `cᵢ、cⱼ` 的分数为 −8、−9，`qⱼ` 对同两件为 −10、−7。正确配对的总分是 −15，对调后的总分是 −19，所以 `D=4`，模型在两种分配中偏好正确的一种。每种分配都恰好使用每件候选一次，候选背景会在作差时抵消。D 为正也可能只有一句单独选对，因此表中另外统计两句都选对的比例。

**正式检验。** C 的两个单侧假设分别对应 `S₀` 和 `S₄₈` 是否在真实登记对应上优于交换标签。固定两张分数矩阵，每次均匀置换查询与正例 UID 的映射，两个方法使用相同置换。做 5,000 次，允许个别固定点。统计量为真实或置换 R@20，计算 `p=(1+#置换统计量≥观察值)/5001`。两个确认性 p 值用 Holm 控制家族错误率 0.05，同时报原始和校正值。按源验证冻结的程序字段数分箱做层内置换另列诊断，其参照是该次置换分布。额外指标与分层不挑最优项替代两个首要结果。

**效应与不确定性。** 同一查询保留原生与校正的两项 0/1 命中，报告“新增命中／丢失命中／净差（百分点）”。置信区间用按项目/家族组重采样的 5,000 次 percentile bootstrap，取 2.5% 与 97.5% 分位。同域两方法共用重采样索引，B 与 C 分别独立重采样。配对诊断以互不重用的二件组为单位。A/B 附重复 L0 原文组的敏感性分析。区间条件于已固定的图库。每个查询与 512 个候选的 512 次打分不能算作 512 个独立样本。数值复算可统一用 NumPy PCG64，置换种子 `2026111901`、bootstrap `2026111902`，子种子取 `int.from_bytes(sha256(f"{base}|{domain}|{analysis}".encode()).digest()[:8], "big")`，记入结果。共享置换或成对抽样的方法使用同一子种子和索引。是否具有工程实用性要另有业务/专用检索基线，主评不将“达到随机的若干倍”定义为可用。

## 7. E1b、E1d · 48 条文字干预与双人几何盲评

**文字干预先于开盲。** 两种改写均从同一英文专家原文独立产生，原文另保留。编辑者根据可核验要求制作 `constraint_id, attribute, value, value_space, explicit_unit, scale_evidence, observable_in_final_solid` 清单。使用人工或机器草拟均可，保义和几何可验证性需有独立复核记录。把原文已有的约束核实清楚，不能把查看目标几何时新发现的线索加进描述。

**数字和人评的共同口径。** `value_space` 分计数、比例、归一化程序值、物理尺寸、尺度不明。分别保存原文、程序字段、参考长度以及单位换算。无单位的尺寸词可以进入按原文字面数值与候选归一化值比较的诊断，但取得物理尺度证据后才能进入物理尺寸基线或裁决绝对大小。每个候选的诊断取数只依赖该候选，与查询是否为其登记文字无关。已查看过的例件 `100155_57ec5fc6_0000`，文字和 minimal 的首个正向挤出深度都为 `0.1369`。Autodesk 原始历史记录该次挤出为 `1.0 cm`，原始包围盒最大边约 `5.48 cm`，乘 `0.75/5.48` 后四舍五入到四位恰为 `0.1369`。在覆盖表标记该例已用于格式核验。这是一个可复算的实例，全库的数值依赖程度由预定基线和文字干预计量。[Autodesk 原始单位](https://github.com/AutodeskAILab/Fusion360GalleryDataset/blob/master/docs/reconstruction.md#units) · [Fusion 专家文字与程序](https://huggingface.co/datasets/chandar-lab/Fusion360-ds/tree/ea7d06f44706ad49cf78f7740c570a8fb8b34f66)

| Qgeom · 去步骤、保几何 | 例如原文表达“在板中央画一直径为 12 的圆，贯穿切除”，可改为“板中央有一个直径为 12 的通孔”。保留原文可验证的孔数、通盲、相对位置、比例和量值。删除画圆、选择平面、执行切除等实现措辞 | 若原文要求特定建模历史且无法保义、与 STEP 冲突、或改写后超长，写明理由。合格改写和对应的原文作配对比较 |
| Qvalue · 隐精确量值 | 在原文上把直径、长度、角度、精确比例等改为语法通顺的非精确表达，并保持其余措辞和条件。如“直径 12 的中央通孔”变为“中央通孔”。保留显式孔数/部件数，将数量与尺寸分开标记。没有精确量值时保留原文并标 `no_edit` | 比较同一查询中的名次、Top-20 双向翻转、百分点差和区间。量值删掉后正确答案可能变多，登记 UID 掉分只表示对该信息敏感 |

原始 48 条均入台账。每一版记 BERT token 数、可核验约束数和相对原文的变化。报告两种改写各自的配对结果，注明同时发生的长度变化与措辞变化。分别报告 `changed_valid / no_edit / unverifiable / overlength`，对 `changed_valid` 报成对诊断，另给相同查询集上的三版本比较及分母。原文或两个改写完全相同时可复用已有行。在相同 C 图库上两种读出都评，`B(c)` 与背景分不随改写改变。48 条的结果用于解释机制，不作为和主表同等规模的新确认性检验。

**前排盲评。** 用原文分别从 `S₀` 与 `S₄₈` 取前 3 件，加入登记件、一个从全图库除登记件外均匀抽取的候选。随机件若与前排重合只呈现一次。每条最多 8 件，共不超过 384 个“文字–零件”单位。保留密封的来源映射，打乱顺序和候选编码。两名标注者独立查看原文及可旋转实体/切面，必要时量取比例。可见的绝对尺寸仅在单位、尺度和参考几何有可靠对应时裁决。模型名、排名、正例身份及另一人评分对标注者隐藏。改写复核与前排相关性标注分别留档。

| 标签 | 决策规则 |
|---|---|
| 全部可核验要求成立 | 显式几何条件均有证据满足 |
| 部分可核验 | 有条件成立也有条件无法核实，尚无明确冲突 |
| 冲突 | 至少一个可验证的显式条件与零件矛盾，记下该条件 |
| 信息不足 | 全无可可靠判定的条件，或视图/尺度等证据不足。仅有建模历史要求的，单列“过程条件” |

先保存两份原始标注，再记录分歧与裁决。每种方法按查询宏平均报告前 3 中“全部成立”的比例、四类分布、登记件自洽率、信息不足率、两位标注者裁决前的一致率。按查询组给区间。一个随机件可帮助解释前排富集程度。该预算不足以建立完整图库 qrels。若双人人评暂未齐备，数值结果和覆盖可独立交付，把语义端点标为待评，不能以自动判断冒充双人盲评。

## 8. 运行顺序、额外计算与交付格式

| 阶段 | 接手者实际动作 | 本阶段完成的判断 |
|---|---|---|
| 1a · 源端与数据 | 校验输入 → 复核第 3 节计数 → 在源验证上开发并冻结 minimal 转换与几何容差 → 两域几何重放/训练暴露排查，核对 Fusion 资产及尺度 | 可从任一入选 UID 追到原始程序、参考实体、输入张量及几何误差。各类拒绝有分母。转换错误优先在源端修复 |

## 9. 预期会看到什么，如何决定下一步

从 G5 出发，候选自身容易生成可能再次抬高少数常见程序的名次。校正可能改变单条查询的检索，而整组双差保持不变。CADmium 的专家描述更具体，也可能使精确量值或步骤措辞成为可辨指纹。这两项都是要检验的解释。结果报告应同时给出能推翻它们的观察。

| 观察 | 这轮能写的结论 | 下一步 |
|---|---|---|
| C 的原生、校正都胜过置换，保义去步骤仍有信号 | 这套冻结生成器在外域专家实例检索中有匹配信息，且所测子集的信号能跨过这类措辞变化 | E2 制作单一几何属性真正决定答案的近似件，测同一要求的生成满足率与辨别率 |
| 原生全库信号不明确。校正能检索，且查询内的校正净差区间支持改善 | 源域选定的校正迁移到了这座图库。若两两配对较好，可同时报告原生分已有可配对的信息 | 查前排候选偏好、半集敏感性和反向结果，再比较另一生成器 |
| 正向全库弱，反向或严格配对有信号 | 在固定一件 CAD 比较描述、或固定两件比较配对时，条件分可区分对应关系。跨候选程序的分数可比性是需要检查的因素 | 对照前排候选出现次数、字段数分布与背景校正对名次的影响 |
| 原生有效，校正配对差可靠地为负 | 当前背景在这个域降低了排名。仅有“一个显著、一个不显著”还不足以推出变差 | 查源背景与目标程序分布。任何根据 C 反馈才改的背景另做后续测试 |
| 原文好，去步骤或隐量值后明显下滑 | 模型对这类文字信息敏感。保义去步骤下降与依赖实现措辞相容，改写后的长度和表达习惯也可能影响模型。删除真实尺寸还会增加合理答案数 | 联合盲评与表面基线，E2 用带真几何核验的单属性配对辨别竞争解释 |
| A 好而 B/C 都弱，或 B 好而 C 弱 | 前者优先排查查询风格，后者优先查跨来源迁移、图库难度和转换。B/C 是两批零件。若编码未决或区间宽，结论写未决 | 在预留家族或新来源复查。不能从单个模型、单一外域推断命令序列路线的上限 |
| 登记件排名低，但前排替代件常满足明确要求 | 单 UID 找回和可接受设计命中存在差距，报告观测到的前排满足率及登记件自洽率 | 实用检索阶段引入多正例评测。前排盲评不估计完整图库召回 |
| 两种评分都接近置换，转换、语义核验和区间足以排除有意义的大信号 | 在已覆盖的模型、文本、程序表示和图库中，未观察到强外域检索效果 | E2 固定同一批要求换生成器，区分生成失败与评分失败 |

**本轮结案问题。** 原生分在 C 有多大信号？校正多找回了哪些查询、又丢了哪些？哪些结论经得起措辞干预，哪些仍可能只是精确值对齐？低分能否用转换、覆盖或多解解释？分别用一张表或一组可复查的 UID 回答，再把实验二建议交还研究负责人。
