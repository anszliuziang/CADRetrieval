## 对分析代码和解释的三项修正

1. **长度基线的 UID 破平不公平。** 原代码 `baseline_length` 在同长度时按 UID 升序排，然而候选构造也用 UID 决定同分次序。原预设产物中的长度基线胜率 **0.384**、mean rank **5.31** 受此影响。Codex 在分析代码提交 `912529573e150ba8e8de2dc3e75a882cc470cf28` 中令所有确定性标量基线按模型臂同一规则处理同分：严格 top-1 需独占最高分，逐对同分计 0.5；新增反向测试，全套 **127 passed**。对同一份已验证原始分数做**事后敏感性复算**后，长度基线胜率 **0.518**、mean rank **2.91**；模型三臂、TF-IDF、空文本与随机基线数字不变。长度基线严格 top-1 仍为 **0/32**，原因是 32 个正例没有一个独占最短长度（7 个并列最短，其余有更短候选）；这个 top-1 不宜作为有说服力的长度基线比较。原预设结果保留不覆盖。事后产物及非自引用清单在共享 OBS `runs/idea01_p1_20260925_r01/codex_p1_tie_review/`，`cvteam6` 挂载核验 **4/4**。
2. **EOS 不会在同候选比较中自动抵消。** 生成器的 EOS log-prob 也依赖 query；32 个程序的 own−other EOS 边际全部非零，均值 **−0.570**（范围 **−2.390 至 +0.652**）。扣除 EOS 后，32/32 程序的边际仍为正、均值 **60.707**，所以主观察依旧成立。Kimi 回填中“同候选 EOS 项相同会抵消”的解释是错误的；self 对 EOS 占负 log-prob 的比例范围实际为 **16.2%–57.6%**，中位 **46.0%**，不应笼统称全部被 EOS 主导。
3. **“显著优于全部基线”和“近似等价设计”超出了已做的检验。** 预设脚本只给每个臂各自的 bootstrap 区间，没有定义/计算成对差异检验或多重比较控制；可报告观察到的差值，暂不作全称统计显著性断言。校正臂未 top-1 的 q12/q13 各有 token Jaccard >0.92 的候选，但 token 重叠不是几何等价证据；尚未编译、比较拓扑/几何或取得独立语义标注。224 个正例-候选对中 103 个 token Jaccard ≥0.5、0 个逐字相同，说明近重复风险需要下一轮核实，不能据此改写本轮 UID 标签。

## 可支持的结论与下一门

本轮支持：在固定配对验证集、固定提示与固定小候选集合上，冻结生成模型的完整 response+EOS teacher-forced 条件 log-prob 对配对文本敏感；其分数能做高于所列词面基线的 **exact-UID 配对排序 sanity**。不支持：开放库语义 CAD 检索指标、设计意图理解、几何等价判断、跨模型优势或校正方法的新颖性。32 query × 8 候选的抽样不保证一般化，模型训练集与验证集的设计家族近重复仍需独立审计。

**下一步先做独立 qrels 与几何等价的可行性门**：固定一个小型候选集，抽样审计 q12/q13 等高相似 UID 对的程序可编译性、几何/拓扑同异与多正例标注来源，并核对 train/validation 设计家族泄漏。先写明确的标注与停门协议，审计通过后再考虑 P2；当前 P2/P3 不获授权。
